# MISSION —— tpa-data-plane 数据面场景课

## 一句话学习目标

按使用场景学懂 tpa-data-plane：**一批数据怎么合法存进湖、一个问题怎么过四道闸变成带出处的答案、这套代码怎么变成线上服务**——学完能用大白话讲清"数据面九个模块各自拦什么"。

## 为什么学（区别于"做什么"）

- 前两课：teach-petro-agent 给了图纸（伪代码），fieldforge 给了造数器（合成数据）。这一课是**真实代码**——面试里被追问"你真写过吗"，这里的每个模块都能指到文件和行号。
- 数据面是"数据中台/湖仓/指标口径/数据治理"这些面试热词的最小真实样本：2,000 行代码，每个词落成一个能跑的模块，没有分布式系统的噪音。

## 验收标准（三条全中才算学完）

1. **覆盖**：总纲覆盖矩阵每格都被某一步讲到（收官逐格对账）。
2. **动手**：四条关键链路亲手复现过——进湖一次、问数一次、被拒答一次、回放一次（云端 API + 本地进程内各走过）。
3. **讲得出**：场景题闯关通过；能脱稿回答"为什么查数前要先过四道闸、少一道会出什么事"。

## 学习规则（Owner 定，全程有效）

- 你说"下一步"才推进；说"提交"才 commit。
- 每步文章交付前过一轮朗读关（全新子 agent 只查阅读性，数值事实由主窗口实测负责）。
- 学习阶段不改生产代码；走线发现的问题记进总纲"发现的问题"节，收官转施工票。

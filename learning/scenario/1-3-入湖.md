## 1 这一步做什么

两个模块接力，各一句大白话（"湖"＝总纲术语表里那个只加不改的大数据池；"写面"＝允许往湖里写数据的入口）：

- **dp2 进料（ingest.py）**＝搬货的规矩：一条叫"三步契约"的流程——**先验、再写、后登记**。没验过的货不许搬；搬的时候必须报身份；搬完还要登记这批货的时效。
- **dp1 湖底座（lake_store.py）**＝湖本身：一个**只许追加、不许修改删除**（append-only：只能往尾部加新数据）的数据池，外加一道"写面白名单"——全系统只允许两个报名字的人写。

这一课的两个关键词：**快照**（湖表每追加一批就自动拍一张"存照"，编号 0、1、2……）和**白名单**（名单上没报名字的，写一个字节都算越界）。

## 2 调用链：一批货走完三步契约

```
洗过的货（1-2 行级闸的出口）
   │
   ▼
┌ dp2 run_batch_load（ingest.py:64）——三步契约 ────────────────┐
│ ① 先验：闸装在搬货流程里——质检不过就整批拒收（程序喊停），   │
│          "写进湖"那一步根本不会执行（不合格批连湖门都摸不到） │
│ ② 再写：begin_caller("dp2.ingest") 报身份 → append 写湖      │
│          dp1 查白名单 → 放行 → 诞生新快照                    │
│ ③ 后登记：新鲜度登记 offline + 数据截至时间（1-4 细讲）       │
└──────────────────────────────────────────────────────────────┘
```

### 站 1 三步契约本体（`ingest.py:64-79` 原文）

```python
    def run_batch_load(self, table: str, records, provenance: Provenance):
        rules = self._rules.get(table)
        if rules:  # 入湖必过质检（DP-W-D2-1：validate 先行，不合格批拒绝入湖）
            from app.data_plane.transform import validate_batch
            report, cleaned = validate_batch(records, rules)
            if not report.passed:
                raise BatchRejected(report)
            records = cleaned
        cat = self.catalog.cat if hasattr(self.catalog, "cat") else self.catalog
        cat.begin_caller("dp2.ingest")  # 写面白名单声明（DP-W-D1-4）
        snap = cat.append(table, records, commit_meta={"provenance": {
            "quality_report_id": provenance.quality_report_id,
            "operator": provenance.operator}})
        self._registry.register(table, tier="offline",
                                as_of=_committed_as_of(), pipeline="batch-shift-report")
        return snap
```

对照三步读：①`validate_batch` 先行，`report.passed` 不成立就报错喊停——**喊停之后，后面写湖的代码根本不会执行**（编程里叫"抛异常"：程序在这里退出，余下步骤全跳过。这叫"闸在编排层"——闸不在湖里，在搬货流程这一层）；②`begin_caller("dp2.ingest")` 报身份，然后 `append`；③登记新鲜度（offline 档、截至时间＝现在，1-4 细讲）。中间那行 `cat = self.catalog.cat if ...` 是兼容小垫片（两种包装都认），不影响主线，跳过。`provenance`（来历档案：体检单编号＋操作人）随写湖动作一起落进快照自带的来历信息里。

（代码注释里的 DP-W-D2-1、DP-W-D1-4 这类编号＝设计文档的验收断言合同编号，可查 `specs/walkthroughs-data-plane.md`；正文不依赖它，当"这句行为是有合同背书的"即可。）

### 站 2 快照怎么诞生（`lake_store.py:162-173` 原文）

```python
    def append(self, table: str, arrow: pa.Table, commit_meta: dict) -> SnapshotInfo:
        if self._caller not in _WRITE_ALLOWED:
            raise BoundaryViolation(
                f"dp1.append 调用方 {self._caller!r} 不在白名单 {_WRITE_ALLOWED}（写面收敛）")
        state = self._tables[table]
        state.current = pa.concat_tables([state.current, arrow])
        info = SnapshotInfo(snapshot_id=state.next_id, committed_at="now",
                            provenance=commit_meta)
        state.next_id += 1
        state.snapshots.append(info)
        state.by_snapshot[info.snapshot_id] = state.current
        return info
```

四行读法：①先查报名字的人（`_caller`）在不在白名单 `_WRITE_ALLOWED`（`lake_store.py:46`：`("dp2.ingest", "dp3.transform")`，全系统就这两个名字）；②新货**接到旧数据尾部**（concat＝拼接，旧行一个都不动）；③发一个新快照编号（next_id 从 0 起，建表那刻就有 0 号"存照"）；④**把此刻的全表钉进 `by_snapshot` 这本存照册**——以后谁要查"1 号快照时的样子"，翻这册子，给的就是当时那张，不受后来追加的影响（这叫快照隔离）。顺带消一个误读：快照≠每批整表复制一份备份——真湖（Iceberg）里新旧版本共享没变过的数据文件，快照约等于记个版本指针，不翻倍占空间。

**实测**（fieldforge 干货前 50 行，分两批入湖）：

```
批1 → 快照 1 | 来历 {'provenance': {'quality_report_id': 'rep-001', 'operator': 'laowang'}}
批2 → 快照 2 | 来历 {'provenance': {'quality_report_id': 'rep-002', 'operator': 'laowang'}}
查 1 号快照（批1 时点）: 50 行
查当前（批2 之后）  : 100 行
新鲜度: FreshnessInfo(tier='offline', as_of=..., pipeline='batch-shift-report')
```

看清楚：1 号快照永远 50 行，哪怕当前已经 100 行。**每个快照的来历都带着体检单编号**——答案可溯源的根子扎在这里。

### 站 3 两道拦挡，实测原文

**拦挡一：脏批拒收**（`ingest.py:16-19`）。塞一批含重复行的货：

```
脏批拒收 → 质检不合格（rule_ids=['rule-1', 'rule-2', 'rule-3', 'rule-5']），批被拒绝入湖
拒收后当前行数: 100（应仍 100，半批都不会进去）
```

注意报错文案的一个坑：**它列的 rule_ids 是"本批跑了哪几条"，不是"挂的是哪几条"**——真挂的只有 rule-1（重复行），要看真实病历得看体检单的 failures。文案不精确，这里如实指出（已记进 0-0 导览总纲"发现的问题"清单，编号 P5，收官统一开施工票修）。

**拦挡二：越界写**（`lake_store.py:163-165`）。冒充查询工具 dp8 想直接往湖里塞数据：

```
越界写被拦 → dp1.append 调用方 'dp8.tools' 不在白名单 ('dp2.ingest', 'dp3.transform')（写面收敛）
```

**拦挡二的另一面，必须诚实交代**：白名单查的是 `begin_caller` **自报**的名字，第一期工程（S1 档，0-0 交代过的"最小可用"档位）没有任何验证——你若冒充 `begin_caller("dp3.transform")`，append 真的能成功（实测成功）。这是"最小可用"档位的如实水平：**闸的逻辑到位了，身份还是自报家门**。真件（Iceberg+对象存储）里，身份验证由存储层的基础设施接管，不靠自觉。防线挡的是"无心之失"（别的模块顺手调 append），不是蓄意冒充。

## 3 服务与中间件卡（2 张）

### 卡一：InMemoryLake——一个"假的湖"

- **它替我们干了件什么体力活**：让"往湖里写数据"这件事，测试里**不装任何软件**就能发生——湖是个内存里的字典，毫秒级建好、跑完就扔。（"替身"是测试领域的标准做法：接口和真品一模一样、内部是简化实现，行话叫测试替身；"真件"＝真正的生产组件。假湖不是玩具——append-only、快照隔离、白名单这些规矩与真件一一对齐，差的只是规模和持久性：内存里的，程序一停就没。）
- **自研还是开源**：替身是自研的（180 行）；它模仿的真件是开源组合 **PyIceberg + MinIO + PostgreSQL**（MinIO＝开源对象存储，拿来当湖的仓库；PostgreSQL 兼当目录）。**真件到本课为止还没挂上**——MinIO 的安装文件在本网络下载不到，这事记在 PRD 的遗留清单里欠着，全仓现在跑的都是这个假湖。
- **本项目怎么配置使用**：`load_catalog(backend)` 的 backend 参数收三种值（jdbc＝走数据库当目录、rest＝走网络接口、federated＝联合查询——现在只需知道这是给真件留的座位）；调用方代码一行不改，换个实现就是真湖。
- **市面上同类有哪些**：真湖仓三大家——Iceberg、Delta Lake、Hudi（都是"快照 + 只加不改"的路数）；更轻的有"Parquet 文件 + DuckDB 直读"（本仓云端 API 走的正是这条，3-1 细讲）。
- **为什么用替身**：①接口先冻结——替身和真件长得一样，调用方永远不用改；②测试要快——98 个测试秒级跑完，装真件做不到；③少一套基础设施依赖（S1 档的规矩）。
- **换场景怎么选**：数据上量、要多个查询引擎共享、要行级权限 → 换真 Iceberg；单机分析、GB 级 → 文件 + DuckDB 已经够（本仓两条路都留了）。

### 卡二：append-only——把"改数据"这条路堵死

- **它替我们干了件什么体力活**：让"数据被改错/被篡改"从根上不可能——想"改"，唯一的方式是追加一个新快照，老版本永远躺在存照册里。
- **自研还是开源**：这是设计决定，不是组件。门面（＝对外只出这一层接口）**故意不提供** overwrite/delete/upsert（改写/删除/更新三个口子全不设，`lake_store.py` 开头注释原文："门面**故意不暴露** overwrite/delete/upsert"）。
- **本项目怎么配置使用**：没有配置——没有入口就是配置。唯一合法的"消失"是 dp7 的滚动清理 `expire`（保留最近 50 张快照，旧的到期清除，而且这个口子也只许 dp7 一个模块调，2-6 讲）。
- **市面上同类有哪些**：三大湖表格式全是此路数；传统数据库支持 UPDATE/DELETE——也是数据事故最高发的两个词。
- **本项目为什么选它**：dp7 的"同快照回放"（按当时的存照重算一遍对质）前提是**历史版本还在**；审计的前提是**过去不可篡改**。"一键删错数据"这类事故，在物理上不可能发生。
- **换场景怎么选**：合规要求真删（隐私数据）→ 用滚动清理到期的路子，照样不给"随手删"；要频繁改写的业务库 → 那就不该用湖，用普通数据库。

## 4 防线对号

- **不合格批连湖门都摸不到**：闸在编排层（`run_batch_load` 第一步），实测拒收后湖里行数纹丝不动。
- **写面越界当场爆炸**：白名单外的 append 抛 `BoundaryViolation`，报错直接念出白名单——让越界者知道规矩是什么。
- **每张快照自来历**：体检单编号＋操作人随写湖动作落进快照自带的来历信息里，答案可溯源的地基（2-6 回放课回收这条线）。

## 5 亲手验证

> 前提同 1-2：打开 macOS 的"终端（Terminal）"应用，两段脚本都**整段一次性复制**粘贴回车（抄漏结尾的 EOF 会卡住）。需要本机有 fieldforge 和 tpa-data-plane 两个仓、干货 out-tpa（fieldforge＝上一门课的造数器，干货＝它的干净产物）、Python 依赖已装（本课环境已装）。

```bash
cd /Users/divh/Downloads/tpa-data-plane
python3 - <<'EOF'
import csv, sys
import pyarrow as pa
sys.path.insert(0, ".")
from app.data_plane.lake_store import InMemoryLake
from app.data_plane.ingest import Ingest, FreshnessRegistry, Provenance
from app.data_plane.transform import RULES_OIL_DAILY

# 货：fieldforge 干货油表前 50 行

                                newline="", encoding="utf-8")))[:50]

# 湖：假湖（卡一），建表即有 0 号快照
lake = InMemoryLake()

cat.create_table("oil_production_daily", schema=schema,
                 comment="日产计量", partition_spec="day(prod_date)")
ing = Ingest(catalog=cat, freshness=FreshnessRegistry(),
             rules={"oil_production_daily": RULES_OIL_DAILY})

# 同一批货分两次入湖 → 快照 1、快照 2

                           Provenance("rep-001", "laowang"))
snap2 = ing.run_batch_load("oil_production_daily", pa.Table.from_pylist(rows),
                           Provenance("rep-002", "laowang"))
print("批1 → 快照", snap1.snapshot_id, "| 来历", snap1.provenance)
print("批2 → 快照", snap2.snapshot_id, "| 来历", snap2.provenance)
```

## 6 捣乱实验（三个递进）

```bash
cd /Users/divh/Downloads/tpa-data-plane
python3 - <<'EOF'
import csv, sys
import pyarrow as pa
sys.path.insert(0, ".")
from app.data_plane.lake_store import InMemoryLake, BoundaryViolation
from app.data_plane.ingest import Ingest, FreshnessRegistry, Provenance, BatchRejected
from app.data_plane.transform import RULES_OIL_DAILY

rows = list(csv.DictReader(open("/Users/divh/Downloads/fieldforge/out-tpa/oil_production_daily.csv",
                                newline="", encoding="utf-8")))[:50]
schema = pa.Table.from_pylist(rows).schema
lake = InMemoryLake()
cat = lake.load_catalog("jdbc")
cat.create_table("oil_production_daily", schema=schema)
ing = Ingest(catalog=cat, freshness=FreshnessRegistry(),
             rules={"oil_production_daily": RULES_OIL_DAILY})
ing.run_batch_load("oil_production_daily", pa.Table.from_pylist(rows), Provenance("rep-001", "laowang"))
t = cat.load_table("oil_production_daily")

# 捣乱一：塞一批带重复行的脏货
bad = rows[:10] + [dict(rows[0])]
try:
    ing.run_batch_load("oil_production_daily", pa.Table.from_pylist(bad), Provenance("rep-003", "laowang"))
except BatchRejected as e:
    print("捣乱一 脏批拒收 →", e)
print("        拒收后当前行数:", t.scan().num_rows, "（应仍 50）")

# 捣乱二：冒充查询工具直接写湖
cat.begin_caller("dp8.tools")
try:
    cat.append("oil_production_daily", pa.Table.from_pylist(rows[:1]), {})
except BoundaryViolation as e:
    print("捣乱二 越界写被拦 →", e)

# 捣乱三：冒充合法写方（自报家门没人查证）
cat.begin_caller("dp3.transform")
cat.append("oil_production_daily", pa.Table.from_pylist(rows[:1]), {})
print("捣乱三 冒充 dp3.transform：居然成功了，当前行数 =", t.scan().num_rows, "（S1 身份=自报家门，课文站 3 交代过）")
EOF
```

应看到：捣乱一整批被拒、湖里行数不变（半批都不进去）；捣乱二被白名单当场拦下并念出名单；捣乱三**成功**——这就是 S1 档"闸逻辑到位、身份靠自觉"的如实水平，也是真件（存储层验证身份）要补的那一环。

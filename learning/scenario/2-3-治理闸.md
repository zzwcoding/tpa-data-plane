## 1 这一步做什么

治理闸管**资格**，不管数据本身——设计文档里那句"闸只持规则不持数据"就是这个意思：它手里只有三样东西（表间连线白名单、作业区清单、用户档案），查询过闸时它只比对、不读数。

两道检查，各管一件事：

1. **check_join（表间白名单）**：这次查询牵扯的表，两两之间允许连线吗？规矩是**默认拒绝**——名单上没写的组合，一律不行。
2. **authorize（行级隔离）**：你这个人（身份+归属作业区），允许看目标表的这个范围吗？油田的规矩是按**作业区**分家：渤中的人看渤中的井，渤南的数不该出现在你的答案里。

另外它立了一条家风：**fail-closed（关死而不是放开）**——身份不明、用户不存在、档案缺归属，一律拒绝。安全系统的选择和日常系统正相反：宁可误拒一个，不可放进一个。

### 站 2 表间白名单：默认拒绝（`governance.py:62-73`）

```python
    def check_join(self, query: StructuredQuery) -> Decision:
        tables = [t for t in query.tables if t != query.base_table]
        edges = {(query.base_table, t) for t in tables}
        violated = []
        for left, right in sorted(edges):
            hit = self._lookup_edge(left, right)
            if hit is None:
                violated.append({"edge": f"{left}⋈{right}", "note": "不在白名单：走治理链审批新增白名单"})
            elif hit.get("status") == "blocked":
                violated.append({"edge": f"{left}⋈{right}", "note": hit.get("note", "")})
        return Decision(allowed=not violated, violated_edges=tuple(violated),
                        reason="" if not violated else "Join 白名单默认拒绝")
```

读法：先认识两个词——**基表**＝查询主角的那张表（数字主要从它出）；**连线**（数据库行话 join，记号 ⋈，读作"连"）＝两表一起算数时必须建立的对应关系。这段代码把查询牵涉的表去掉基表，剩下每张跟基表凑成一条连线，逐条查名单——**没查到就是违规**（连"这条边还没审过"都给你一句指引：走治理链审批新增）。为什么默认拒绝而不是默认放行？名单外的组合是**无穷多**的，名单内是**可枚举**的——防无穷的东西只能靠列清单。假想反例：如果反过来"默认允许、只拦黑名单"，就得靠各处代码自觉判断"这条连线危险吗"——全系统六处各写各的，半年后三处已经互相不一致（"逻辑漂移"＝同一规矩各处慢慢变得不一样），谁也说不清哪条边被谁放过过。

**实测**（含一个诚实交底）：

```
dp4 编译产物（单表查询）   → 放行
手造查询连 fluid_test      → 拒！"不在白名单：走治理链审批新增白名单"
```

第一行暴露一个 S1 档（最小可用第一期）的实情：2-2 讲过，dp4 编译出来的查询**永远只有基表一张**（"按区块分组"这类分组列直接在主表上取，不需要第二张表），所以白名单在自动流水线上**暂时没有牙**——它真正防的是将来多表查询和任何"手造查询"混进来。闸的逻辑和合同是真的，只是 S1 的上游还喂不出它想拦的东西。

### 站 3 行级隔离：authorize 全文（`governance.py:84-105`）

```python
    def authorize(self, ctx: UserContext, table: str, action: str,
                  requested_scope: str | None = None) -> Decision:
        """fail-closed：无身份 / 用户未知 / 用户无 org / scope 无法确立 → 一律拒绝。"""
        if ctx is None:
            return Decision(allowed=False, reason="无调用身份（fail-closed）")
        u = self.policy.user(ctx.user_id)
        if u is None:
            return Decision(allowed=False, reason=f"未知用户 {ctx.user_id}")
        if action == "export":
            return Decision(allowed=False, reason="S1 导出整体降级为不可用（DP-W-D9-3 属 S2+ 审批位）")
        user_org = u.get("org")
        if not user_org:
            return Decision(allowed=False, reason="用户档案缺归属作业区（fail-closed）")
        if ctx.role == "admin":
            return Decision(allowed=True)  # 管理员不受作业区清单/行级约束
        scope = requested_scope or user_org
        if scope not in self.policy.row_scope.get("orgs", []):
            return Decision(allowed=False, reason=f"scope {scope} 不在合法作业区清单")
        if scope != user_org:
            return Decision(allowed=False,
                            reason=f"行级隔离：{user_org} 作业区用户不可读 {scope} 井数据")
        return Decision(allowed=True)
```

十一行按顺序读，分四段：**前四段检查全是"直接拒"**（没身份 / 查无此人 / 要导出 / 档案缺归属——每段一句明说原因的拒绝，不给猜）；**第五段是唯一旁路**（admin＝管理员，不过作业区检查）；**最后三行是主判断**——看你要的范围（scope＝权限范围）：不在合法清单里拒，越出自己作业区拒，剩下的放行。其中 `scope = requested_scope or user_org` 这行的 or 是编程语义：**前一个没给，就用后一个**（"没填就用默认"，不是二选一）——记住这行，站 4 出事。实测矩阵（老王＝渤中工程师）：

| 请求 | 结果 |
|---|---|
| 读自己区块（scope=渤中） | ✅ 放行 |
| 读渤南 | ❌ "行级隔离：渤中 作业区用户不可读 渤南 井数据" |
| **不声明范围** | ✅ **放行**（scope 回落成用户自己的渤中——记住这行，站 4 出事） |
| 导出 export | ❌ "S1 导出整体降级为不可用" |
| 无身份 / 未知用户 | ❌ fail-closed |
| admin 读渤南 | ✅ 放行（旁路） |

（"导出"行理由里的 DP-W-D9-3＝设计断言编号，读法 1-3 交代过；S2+＝第二期以后的工程档位。）

注意"导出"这一行：S1 没做导出功能，闸的表态不是"悄悄没有"，而是**明说"整体降级不可用"**——功能可以不做，但不能装着有。

### 站 4 重头戏：P7 现场——沉默能全拿，开口反被拦

把 2-1 的疑点验成真枪实弹。搭一条真实的本地全链（假湖＝1-3 的内存替身湖、DuckDB＝内嵌查询引擎直读文件、数据用 fieldforge＝上一门课造数器的干货），让老王问同一个问题，只差"带不带区块过滤"：

```
老王（渤中）不带过滤问 9 月完成率 →
  [('渤中', 91.6), ('渤南', 92.1), ('渤西', 92.7)]     ← 三个区块全回来了！

老王（渤中）点名 filters={"block_name":"渤南"} →
  拒！gate=dp9.authorize "行级隔离：渤中 作业区用户不可读 渤南 井数据"
```

荒诞但真实：**喊出"我要渤南"被拦；一声不吭，三个区块全拿**。根因是两个环节合力：①站 3 那行 `scope = requested_scope or user_org`（or＝没给就用默认）——范围由调用方**自报**：明说渤南，闸按渤南查（拒）；不说，闸按"你自己的渤中"放行；②**执行引擎根本没拿这个范围去筛数据**（引擎的 SQL——查询语句——里没有"按区块筛选"那一段，即没有 WHERE 子句）——闸以为放行的是"渤中的数"，实际放过去的是全部。2-1 的另一半（describe 点名不传范围）同根同源。已挂总纲 **P7**，修法两条写明：引擎侧按用户作业区强制加筛选（把闸的想法落到数据上），或闸侧拒绝"不声明范围"的查询（宁严勿漏）。修掉之前，"行级隔离"的准确读法是：**只防明抢，不防沉默**。

## 3 服务与中间件卡（2 张）

### 卡一：安全闸的两条家规——默认拒绝 + fail-closed

- **它替我们干了件什么体力活**：把"安全"从"记得拦"变成"忘了也不放过"。
- **默认拒绝**：join 白名单没写的组合一律不行（站 2）。防的对象是无穷集（所有没想过的表组合），只能列清单反着防。同类：防火墙规则、机场安检（没报备的液体都是可疑的）。
- **fail-closed**：信息不全时**拒绝**而不是放行（站 3 前三连击）。反面叫 fail-open：门禁系统停电时门是开还是关？开=方便但失控，关=麻烦但安全。闸选"关"。
- **自研还是开源**：规矩是自研的（静态政策 StaticPolicy，YAML/dict 加载）；行业里同类叫策略引擎/权限模型（AWS IAM 的"默认拒绝"、数据库行级安全 RLS 全是此路数）。
- **本项目为什么这么选**：数据面是最后防线，误放行的代价（数据泄露、口径污染）远大于误拒的代价（多问一次）。
- **换场景怎么选**：对外服务、涉密数据 → 两条例行照抄；内部工具、误拒成本极高 → 可以局部 fail-open，但要写明。

### 卡二："显式不可用"也是功能

- **它替我们干了件什么体力活**：S1 没做导出，闸的回答不是报错堆栈、也不是假装有这功能，而是一张说明卡："整体降级为不可用，属 S2+ 审批位"。
- **自研还是开源**：自研约定。
- **同类**：API 设计里的 501 Not Implemented vs 404；菜单里灰掉的按钮 vs 没有按钮。
- **为什么值得单独立卡**：给 Agent 调用的接口，"功能不存在"必须可辨认——Agent 拿到"显式不可用"会死心换路，拿到含糊报错会反复重试。诚实的边界声明本身就是防线的一部分。
- **换场景怎么选**：砍功能时留一个"明说没有"的壳，比删干净更负责任。

## 6 捣乱实验：复现"沉默全拿"

```bash
cd /Users/divh/Downloads/tpa-data-plane
python3 - <<'EOF'
import sys
sys.path.insert(0, ".")
from app.data_plane.governance import Governance, StaticPolicy, UserContext
from app.data_plane.semantic import StructuredQuery

gov = Governance(StaticPolicy({
    "join_whitelist": [{"left": "oil_production_daily", "right": "well_info", "status": "allowed"},
                       {"left": "oil_production_daily", "right": "fluid_test", "status": "blocked",
                        "note": "化验数据禁止与产量直连（口径未审）"}],
    "row_scope": {"column": "block_name", "orgs": ["渤南", "渤中", "渤西"]},
    "users": [{"user_id": "laowang", "org": "渤中", "role": "engineer"}]}))
lw = UserContext("laowang", "渤中", "engineer")

# ① 手造一条连化验表的查询（白名单标了 blocked）
q = StructuredQuery("x", "oil_production_daily", ("oil_production_daily", "fluid_test"),
                    (), (), (), {}, None)
d = gov.check_join(q)
print("① 连化验表 →", "放行" if d.allowed else f"拒 | {d.violated_edges[0]['note']}")
# ② 同一条边解禁再试（按名字找到那条边改，别按位置——政策顺序可能变）
for e in gov.policy.join_whitelist:
    if e.get("right") == "fluid_test":
        e["status"] = "allowed"
print("② 解禁后   →", "放行" if gov.check_join(q).allowed else "拒")
EOF
```

应看到：①被拒，理由是政策里写的那句"化验数据禁止与产量直连"——**blocked 边连拒绝理由都能定制**；②把政策里该边的 `status` 改成 allowed（内存里改，文件没动），同一查询立刻放行——闸的行为完全由政策文件驱动，这就是"只持规则不持数据"。（脚本第一段里 `StructuredQuery("x", 基表, 牵涉的表, …)` 那串位置参数依次是：指标名、基表、牵涉表集合、算法列、维度、时间维、过滤、行数上限——照抄即可。）

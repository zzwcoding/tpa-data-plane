## 1 这一步做什么

为什么问句不能直接变成查询？因为**油田的话，一 词多义、正别名混、还有禁话**：

- "老完成率"——设计文档里明令禁用的词（口径有争议，用了就要闹误会）；
- "剔检产量""时率"——别名和缩写，说的是"净产量（有效产量·检修剔除）""抽油机时率"；
- "躺井"——作业区黑话（停产待检泵），圈内人懂，得限定语境；
- "有效产量"——**一词两义**：可以指"按开井日历折算"，也可以指"把检修日剔除"，两个数差得不少。

这些不是编程问题，是**业务口径问题**。数据面的解法：把口径写成一本**机器可读的字典**（YAML 文件，人也能直接读），让代码照字典办事——字典说这个词禁用就拦下，说两义就反问，说别名就改写。**代码不发明口径，只执行口径**。

## 2 调用链：一句人话过三道小门

```
"老完成率多少？"
   │
   ▼
门 A：术语归一（resolve_term）——查黑白名单
   │   禁用词→拦 / 别名→改写成正式名 / 黑话→放行但限语境 / 两义→须消歧
   ▼
门 B：查指标卡（metric_def）——这名字在字典里有卡吗？
   │   有卡→拿走口径（公式/单位/粒度/归属表）；没卡→查无此项
   ▼
门 C：编译（build_query）——组装"结构化查询"
   │   单口径→直接编；多口径→检查修饰词，没给就反问（Clarify）
   ▼
结构化查询 StructuredQuery（四件套的前身；四件套＝0-0 术语表里的"数字＋快照号＋质量状态＋数据截至"）→ 交给闸① 治理（2-3）
```

### 站 1 字典本体（`semantic_dictionary.yaml`）

字典三段：**15 张指标卡**、**5 条术语**、**权威源仲裁表**。看一张真的指标卡（原文节选）：

```yaml
  - name: 产量完成率
    version: 0.1.0
    definition: 实际产油与计划配产之比
    formula: "Σ(实际产油)/Σ(计划配产)×100"
    unit: "%"
    granularity: 月
    owner: 开发室
    sql_table: oil_production_daily
    additive: false
    agg: { num: oil_output, den: plan_output, mul: 100 }
    ai_context: 计划版本切换日存在双值行（配产口径争议）
```

一张卡就是**一个数字的户口本**：叫什么、怎么算（formula）、什么单位、按月还是按日（granularity＝粒度）、归谁管（owner）、数在湖里哪张表（sql_table）、能不能把各处的数加总（additive，"产量完成率"这种比值就**不能**跨期相加）。最后 ai_context 连"这个口径容易在哪儿吵架"都记了。卡上那个 `agg` 槽位是 formula 的机器可读版：num＝分子列、den＝分母列、mul＝乘数——三个缩写拼起来正是"实际产油÷计划配产×100"。（"槽位"＝卡上预留的格子。）

再看 5 条术语（全文引用）：

```yaml
terms:
  - term: 老完成率
    action: block
    canonical: 产量完成率
    note: 禁用词（设定书 §6），替代=产量完成率
  - term: 剔检产量
    action: rewrite
    canonical: 净产量（有效产量·检修剔除）
    note: 别名归一
  - term: 有效产量
    action: clarify
    canonical: 有效产量
    note: 一词两译（开井日历/检修剔除），须修饰词消歧
  - term: 躺井
    action: pass
    canonical: 躺井
    note: 黑话=停产待检泵，限作业区语境
  - term: 时率
    action: rewrite
    canonical: 抽油机时率
    note: 缩写归一
```

四种动作正好对应业务的四类词：**禁用词**（block）、**别名/缩写**（rewrite，改写成正式名——这个动作叫"归一"：把各种叫法统一成一个正式名）、**黑话**（pass，放行但备注限语境）、**歧义词**（clarify，必须"消歧"＝消除歧义，让问的人选清楚）。词表内容逐字来自设计文档的术语规范——代码零发明。

### 站 2 门 A：术语归一（`semantic.py:134-138` 原文）

```python
    def resolve_term(self, term: str) -> TermResolution:
        for t in self.backend.terms():
            if t["term"] == term:
                return TermResolution(canonical=t["canonical"], action=t["action"], note=t["note"])
        return TermResolution(canonical=term, action="pass", note="")
```

九行读法：逐条扫术语表，词对上了就把"正式名+动作+备注"带回来；**没上名单的词默认放行**（action="pass"）。实测六个词：

```
'老完成率'  → block    禁用词，替代=产量完成率
'剔检产量'  → rewrite  → 净产量（有效产量·检修剔除）
'躺井'      → pass     黑话=停产待检泵，限作业区语境
'时率'      → rewrite  → 抽油机时率
'有效产量'  → clarify  一词两译，须修饰词消歧
'支持率'    → pass     （没上名单，默认放行）
```

### 站 3 门 B+C：查卡与编译，一词两义不擅断（`semantic.py:142-169`）

编译的主干判断就一处（节选）：

```python
        measures = tuple(card.get("measures", ()))
        if len(measures) > 1:  # 一词多 measure（裁决：消歧在本层，DP-W-D4-2——DP-W 开头的编号＝设计文档的验收断言编号，1-3 交代过读法）
            modifier = filters.get("口径")
            if modifier not in card.get("modifiers", []):
                return Clarify(metric=metric, options=list(card.get("modifiers", [])),
                               note=card.get("ai_context", ""))
            chosen = self._measure_for(card, modifier)
```

大白话：这张指标卡如果带**不止一个算法**（measures 有多项），就看问句里带没带"口径"这个修饰词——没带或带的不在候选里，**返回一张"反问卡"（Clarify）**：候选是什么、为什么问（把卡上的争议备注原文带上）；带了合法的，才按选的那支编。**宁可反问，不替用户拍板**——这跟 dp6 的"零编数"是同一个家族的纪律：不猜。

实测三连：

```
问"产量完成率"（单口径）→ 直接编成结构化查询：
    base_table=oil_production_daily, measures=('产量完成率',),
    窗={dateRange:[2025-09-01, 2025-09-30], granularity:'month'}, limit=None（行数上限没设）

问"有效产量"不带修饰 → 反问卡 Clarify：options=['开井日历','检修剔除']
    note='跨月检修切割争议；修饰词消歧在语义层…'

问"有效产量"+口径="检修剔除" → 编译成功：
    base_table=fct_valid_output_monthly, measures=('valid_output_overhaul_excluded',)
```

注意三个结果各有各的去向：单口径与"检修剔除"两支编到了**不同的表**（后者带检修信息才能算）；反问卡带着候选清单和争议备注原文。编译产物 **StructuredQuery**（结构化查询）逐槽位认识一下（`semantic.py:71-80`）：指标名、基表名、牵涉的表、算法列、维度（按什么分组统计，数据库行话叫 group by）、时间窗（起止+粒度）、过滤条件、行数上限。**从这一刻起，"人话"消失了**——后面四道闸只见结构化查询，谁也不用再理解自然语言。

### 站 4 零发明纪律与出处

- **口径只许来自字典**：设计边界规则原文"dp4 发明口径——指标定义只来自 dp3 manifest 与设定书——语义层是口径唯一暴露面，禁止第二真源"。字典里没有的指标，`build_query` 当场抛"查无此项"错（编程写法 raise KeyError，`semantic.py:146`）——语义层抛错是**对的**；这正是总纲"发现的问题"P3 的现场：网站层没接住这种错、回了句服务器错，收官一起修。
- **湖表口径要对账**（`semantic.py:178-191` 对齐闸）：凡是口径卡指向汇总表（fct_ 开头）的，自动核对"这张表在不在构建清单里、列名对不对得上"——字典说的和湖里实际有的，必须对上。
- **一数四源，仲裁有主**：同一件事多个来源报数（计量、化验、实时、上报），字典的权威源段裁决认谁。实测：

```
问"油气产量"的权威源 → monthly_settlement（E7 统计上报）
   备注原文：A11 实时加和 vs E7 统计上报差 3.2%（事故 13，教学值）；
   实时面仅日内趋势可用，正式月度口径以离线面月结为准
```

（A11、E7＝设定书里两套报数系统的代号：A11 抓实时加和、E7 是正式统计上报；"事故 13"＝设定书事故簿第 13 号案例——两套数差 3.2%，谁对谁错吵出来的教训。）

这段备注会在 2-4 路由课再次登场——实时面作答时必须原样带上的"口径差异声明"就是它。

- **出处工具**（2-1 预告的 lineage，即"血缘"——数从哪来）：实测问"有效产量"的出处，答 `source_table=fct_valid_output_monthly`——出处即字典里的 sql_table，**口径在哪定义，数就从哪来**。（如实交底：S1 档的 lineage 只报基表，不展开完整血缘树——完整版在 dp3 的构建清单里，3-3 收官对账。）

## 3 服务与中间件卡：口径为什么要"机器可读"

- **它替我们干了件什么体力活**：把"这个数怎么算、哪个词什么意思"从开会纪要、老师傅脑子里，搬进一个文件——让程序查口径跟查电话本一样快，且**全公司查到的是同一本**。
- **自研还是开源**：本仓是自研 YAML 字典（15 张卡，零依赖）；行业里的同类叫"语义层/指标中台"——Cube（开源语义服务）、dbt 的语义层、各家指标平台。设定书的 15 张指标卡在行业里就叫 headless BI（无界面指标服务）的底座。
- **本项目怎么配置使用**：字典是数据面里**唯一**能改口径的地方；代码加载它、照它办事；想改口径＝改字典（下一节捣乱实验当场演示"字典一改闸门立变"）。
- **市面上同类有哪些**：Excel 口径手册（人读，会过期）、散落在 SQL 注释里的口径（会漂移）、语义层服务（机器读，唯一真源）。
- **本项目为什么选 YAML 不选语义服务**：15 张卡的体量，YAML 一人能读、机器能读、零依赖——语义服务是 S2+ 留位，等指标上百张、多团队共用再上。
- **换场景怎么选**：口径 ≤50 条、一个团队 → YAML 够；多团队多引擎共享指标 → 上语义层服务，但**先把口径写成卡**这一步怎么都省不掉。

## 4 防线对号

- **禁用词闸**：'老完成率' 一进门就 block——口径争议在词头上就掐断，不带进计算。
- **不擅断**：两义词必反问（Clarify），跟 dp6 的零编数同族——**系统的诚实从翻译阶段就开始**。
- **零发明＋对齐闸**：字典没卡＝查无此项；说有汇总表就必须真有（站 4）。
- **P3 现场**：没接住"查无此项"是网站层的事故，语义层本身的行为是对的（当场抛错、拒绝编）。

## 6 捣乱实验：篡改字典，看闸门立变

```bash
cd /Users/divh/Downloads/tpa-data-plane
python3 - <<'EOF'
import sys, yaml
sys.path.insert(0, ".")
from app.data_plane.semantic import Semantic, StaticYaml

sem0 = Semantic(StaticYaml.default())
print("原字典: 躺井 →", sem0.resolve_term("躺井").action)          # pass（放行）

data = yaml.safe_load(open("app/data_plane/semantic_dictionary.yaml", encoding="utf-8"))
for t in data["terms"]:
    if t["term"] == "躺井":
        t["action"] = "block"                                      # 篡改：黑话改禁用
sem1 = Semantic(StaticYaml(data))
print("篡改后: 躺井 →", sem1.resolve_term("躺井").action)          # block
EOF
```

应看到：**同一个词，字典一改，判决立刻从 pass 变 block**（原文件一个字节没动——改的是"内存里的副本"：只在本次运行的临时数据里改，没写回文件，程序一停就消失）。这就是"字典即闸门"：口径治理的最后落点不是文件，是加载它之后系统的行为。

# 2-1 五只读工具 dp8：问数的 Agent 只被允许做五个动作

> 场景 2 开场。场景 1 把数据备进了湖；现在有人来问数了。问数的是另一个工程——问数 Agent（背后是大模型，本仓不管它）。它和数据面之间**只有一扇窗**：五个工具。本课讲这扇窗为什么长这样。

**你在这里**：

```
场景 2 老王问数：一个问题走完四道闸
[x] 2-1 五只读工具与只读红线   ← 你在这里
[ ] 2-2 问句变查询 dp4：术语黑白名单、一词两义消歧
[ ] 2-3 治理闸 dp9：表间白名单 + 作业区行级隔离
[ ] 2-4 路由与拒答 dp6：三查三出口、话术不编数
[ ] 2-5 执行与成本护栏 dp5：DuckDB 真算
[ ] 2-6 记账与回放 dp7：答案钉在快照上
──────────────
场景 3 从代码到线上服务（3 步） → 收官
```

---

## 1 这一步做什么

问数 Agent 是个"会说话的中间人"：听用户说人话，组织答案。它很聪明，但也可能"手滑"——如果没有约束，它完全可能想出"我直接连数据库把数改了/把表删了/把别人区块的数捞了"这种动作。数据面的应对是**物理收窗**：

1. Agent 能做的动作只有**五个**，全在这份清单里（`tools_mcp.py:15`）：

```python
_TOOL_NAMES = ("discover_tables", "describe_table", "query", "replay", "lineage")
```

2. 五个全是**只读**的：看有什么表、看表长什么样、问一个数、对质一个旧答案、查一个数的出处。没有任何一个能写、能改、能删。
3. "只读"不靠自觉，靠**机器检查**：有一个专门的检查函数盯着工具清单，谁敢加一个带写动作的方法，测试当场翻脸（站 2 实测）。

设计文档里管这扇窗叫**唯一接缝**：Agent 一切需求都从这五个口进，绕不过去——所以四道闸（后面五课的主角）才能"每条查询必经"。

## 2 调用链：五个口各通向哪里

```
问数 Agent（另一个工程，本仓之外）
   │  只认五个工具名
   ▼
┌ dp8 DataTools（tools_mcp.py）——唯一接缝 ─────────────────────────┐
│ ① discover_tables  湖里有哪些表（越权的不给看，也不告诉你在）     │
│ ② describe_table   这张表长什么样（结构卡）                      │
│ ③ query            问一个数 —— 串起四道闸（本课只看骨架）        │
│      闸① dp9 治理：表间连线白名单＋作业区行级权限（2-3）          │
│      闸② dp6 路由：该不该答、答哪套数据（2-4）                    │
│      闸③ dp5 执行：真算＋成本护栏（2-5）                          │
│      闸④ dp7 记账：答案钉上快照号（2-6）                          │
│ ④ replay           拿旧答案的编号重算对质（2-6）                  │
│ ⑤ lineage          这个数的出处（2-2 带一句）                     │
│ ⑥ write_intent     不是工具——是"想写"时的专用拒绝窗口（站 4）     │
└───────────────────────────────────────────────────────────────────┘
```

### 站 1 五个口，各一句大白话

| 工具 | 干什么 | 输入 → 输出 |
|---|---|---|
| discover_tables | "这湖里有哪些表我能看？" | 前缀（可不填）→ 表卡清单（名字/档位/截至/挂了哪些指标） |
| describe_table | "这张表长什么样？" | 表名 → 结构卡（列/分区/挂的指标） |
| query | "渤南上月产量完成率多少？" | 指标+维度+时间窗+过滤 → 四件套答案（或结构化拒答） |
| replay | "把之前那个答案按当时的数据重算一遍" | 答案编号 → 两次结果+是否一致 |
| lineage | "这个数是从哪算出来的？" | 表名或指标名 → 出处链 |

### 站 2 只读红线怎么"机查"（`tools_mcp.py:16-35` 原文）

```python
_WRITE_VERBS = {"insert", "update", "delete", "create", "drop", "append", "write", "overwrite"}

_REFUSAL_SINKS = {"write_intent"}  # 拒绝 sink：名字含写动词但语义=拒绝写意图（只读红线的执行者）

def audit_write_surface(tools_cls=object) -> dict:
    """只读红线机查（DP-W-D8-3）：五工具、零写动词、附录面收敛。

    名字含写动词的方法只允许是"拒绝 sink"（write_intent），其余即违规。"""
    names = set(_TOOL_NAMES)
    if tools_cls is not object:
        names = {n for n, _ in inspect.getmembers(tools_cls, predicate=inspect.isfunction)
                 if not n.startswith("_")}
    write_hits = {n for n in names
                  if any(v in n.lower() for v in _WRITE_VERBS) and n not in _REFUSAL_SINKS}
    return {"tools": len(_TOOL_NAMES), "write_surface": len(write_hits),
            "violations": sorted(write_hits),
            "refusal_sinks": sorted(set(names) & _REFUSAL_SINKS),
            "readonly": not write_hits}
```

大白话：拿一张"写动作词表"（insert/update/delete/create/drop/append/write/overwrite 八个词），扫工具类里的每个方法名——**名字里含写词的，只许是 write_intent 这一个"专门用来拒绝的口"**（代码注释里的"拒绝 sink"就是这个意思：sink＝终点、汇——写词请求的专门终点，一律被拒；下文叫"拒绝口"），其余一律记违规。引用原文里"附录面收敛"是设计文档行话，读不懂没关系，下面这句就是它的大白话：**能写数据的口子，一个都不许有**。实测真工具类：

```
{'tools': 5, 'write_surface': 0, 'violations': [], 'refusal_sinks': ['write_intent'], 'readonly': True}
```

这个函数挂在自动化测试里——**任何人往后加一个能写的方法，测试立刻变红**。"只读"从口头纪律变成了机器守的门。

诚实说边界：机查按**名字**判断，会误伤——一个只读方法如果起名叫 `overwrite_preview`（覆盖预览，其实是"看一眼"），也会被拦（实测会）。安全检查宁可错杀不放过，唯一的豁免口是 `_REFUSAL_SINKS` 名单。想要更聪明的判断（看方法内容）成本高很多，S1 档（最小可用第一期，0-0 交代过）选择了最笨但最不会漏的一版。

### 站 3 发现与描述的门槛：越权表"藏"起来（`tools_mcp.py:51-64`）

```python
    def discover_tables(self, prefix: str | None = None,
                        ctx: UserContext | None = None) -> list[dict]:
        ctx = ctx or self.default_ctx
        cards = []
        for name, meta in sorted(self.catalog_tables.items()):
            d = self.governance.authorize(ctx, name, "read",
                                          requested_scope=meta.get("scope"))
            if not d.allowed:
                continue  # 越权表不进清单，不报错
            if prefix and not name.startswith(prefix):
                continue
            cards.append({"name": name, "tier": meta["tier"],
                          "freshness": meta["freshness"], "metrics": meta["metrics"]})
        return cards
```

最关键一行：`continue  # 越权表不进清单，不报错`。你没有权限的表，不是报错"无权访问"（那等于告诉了你它存在），而是**清单里压根没有它**——像没这回事。

**实测**：造一个渤中用户、两张表（一张挂渤中权限范围、一张挂渤南权限范围；权限范围＝这张表的数归哪个作业区看）：

```
渤中用户的表清单: ['oil_production_daily']        ← 渤南那张被藏了
直接描述渤南表: {'columns': [], ..., 'metrics_linked': [], 'tier': 'offline'}   ← 没拦住！
```

第二行是本课实测抓到的**真问题**：清单把越权表藏住了，但 `describe_table` 直接点名时**没有把表的权限范围传给权限闸**（对比 `discover_tables` 传了，describe 没传）——于是点名就能拿到越权表的说明卡。好在只露"表长什么样"的说明卡，真正的数据仍被查询闸拦着。已记进 0-0 总纲"发现的问题"（**P7**，1-2 交代过这套记账流程），收官统一开票修；修法一行：describe 也把权限范围传进去。

### 站 4 想写怎么办：专用拒绝口（`tools_mcp.py:137-140`）

先强调：write_intent **不是第六个工具**——它是五个工具之外的一扇小窗，专门接住"想写"的意图。任何一个写词的请求落进来，回答永远是同一张卡：

```python
    def write_intent(self, verb: str) -> dict:
        return {"refused": True,
                "fix": "写路径走 dp2 进料/dp3 加工管道——入湖必过质检",
                "reason": "工具面只读"}
```

三行的意思：被拒了（refused: True）、为什么（工具面只读）、该怎么走正路（去进料管道）。

Agent 真起了写心思（比如想"update 一下数据"），调用任何写词都会落到这个口——回答永远是"拒绝 + 指路"：想写？走进料管道去，那里有质检闸等着。**拒绝不是甩脸子，是指路**：告诉它合法的路在哪。

### 查询的四道闸骨架（`tools_mcp.py:81-118`，本课只立骨架）

`query` 是五个工具里最重的，内部把四道闸按固定顺序串成流水线：先把问句翻成结构化查询（2-2）→ 闸① 权限：能不能查、能不能看这个区块（2-3）→ 闸② 路由：该不该答、答哪套数据（2-4）→ 闸③ 执行：真算（2-5）→ 闸④ 记账：答案钉上快照（2-6）→ 输出答案四件套（0-0 术语表：数字＋快照号＋质量状态＋数据截至）。**任何一道闸拒，整条查询拒——不留部分结果、不记审计**。骨架今天立在这，后面五课逐闸拆。

## 3 服务与中间件卡（2 张）

### 卡一：为什么是"唯一接缝"，而不是给 Agent 一个数据库账号？

- **它替我们干了件什么体力活**：把"AI 可能乱来"这个问题变成不可能——不是教育 AI 守规矩，是**除了这扇窗它根本碰不到数据**。
- **自研还是开源**：接缝是自研的；但"工具清单"这个形态来自开放协议 **MCP**（Model Context Protocol，AI 工具调用的行业协议——让大模型按标准清单调用外部工具）。
- **本项目怎么配置使用**：S1 是"进程内直调"（in_process：Agent 和数据面在同一个程序里直接调函数，不隔网络）；`serve_mcp()` 实测输出：`{'server_name': 'petro-data-plane', 'tools': [五个], 'readonly': True, 'transport': 'in_process（S1；MCP server S2+ 留位）'}`（四个键依次＝服务名/工具清单/是否只读/调用方式）。
- **市面上同类有哪些**：给 AI 接工具的三条路——①给个数据库账号让它写 SQL（快但失控）；②自定 HTTP 接口（可控但每家一套方言）；③MCP 标准协议（清单自描述、跨家通用，行业新标准）。
- **本项目为什么选第三条路的形状**：①五工具即合同——闸的顺序、只读红线都能机查；②审计必经——所有查询都从这一个口过，记账（dp7）才不会漏；③将来换 MCP server 对外，工具清单原样搬。
- **换场景怎么选**：内部 Demo → 进程内直调最省；对外给第三方 Agent 用 → 一定上标准协议（MCP），别自造方言。

### 卡二：拒绝也要有"合同"（结构化拒答）

- **它替我们干了件什么体力活**：让 Agent 每次"没拿到数"时，拿到的不是一句人话或一个报错，而是**结构化的拒绝卡**（哪道闸拒的、原因、改怎么问/走哪条合法路）。
- **自研还是开源**：自研约定。全仓所有拒绝长一个样：`{"refused": True, "gate": 哪道闸, "reason": 原因}`（True＝"是、被拒了"；这三个键＝被拒/拒在哪/为什么。站 3 的 describe、站 4 的 write_intent、1-4 的拒答话术，全是这个形状）。
- **为什么重要**：Agent 是程序，它拿到"结构化拒绝"能自己决定下一步（换问法/走管道/如实告诉用户），拿到"报错堆栈"（程序出错时吐出的一大段技术追踪文本）只会卡死。**对人诚实，对机器结构化**——这套合同 2-4 的拒答话术课会再进一步。
- **换场景怎么选**：任何给 AI/自动化调用的接口，错误返回都该结构化＋带修复指引；这比多写十个成功接口更影响可用性。

## 4 防线对号

- **只读红线机查**：`audit_write_surface` 挂在测试里，写方法一冒头测试就红（站 2 实测，含误伤的诚实边界）。
- **越权静默隐藏**：discover 对越权表"当不存在"（站 3）；但 describe 点名有漏（P7 现场已挂账）。
- **拒绝 sink**：写意图一律进 `write_intent` 拒绝＋指路，无旁路。

## 6 捣乱实验：你亲手当一次"违规者"，看机器怎么抓

```bash
cd /Users/divh/Downloads/tpa-data-plane
python3 - <<'EOF'
import sys
sys.path.insert(0, ".")
from app.data_plane.tools_mcp import audit_write_surface

class Sneaky:                                    # 狡猾版：写方法起了个不起眼的名字
    def discover_tables(self, prefix=None): return []
    def quietly_drop_rows(self, table): pass     # 名字带 drop —— 照样该抓

class WronglyAccused:                            # 反例：只读方法，名字却带写词
    def discover_tables(self, prefix=None): return []
    def overwrite_preview(self): return []       # 只是"看一眼会覆盖成什么"，并不写

print("狡猾写方法:", audit_write_surface(Sneaky))
print("冤枉读方法:", audit_write_surface(WronglyAccused))
EOF
```

应看到两行都是 `readonly: False`：狡猾的写方法被抓住（机查永不放过写动作）；只读的 `overwrite_preview` 也被拦（误伤——机查只看名字不看内容）。两轮玩下来两个手感：**第一品质是不漏，第二品质才是不冤**。

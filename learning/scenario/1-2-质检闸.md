## 1 这一步做什么

fieldforge 交货时附了体检报告（manifest 的 gate 段＝说明书的体检段，1-1 读过：19 过 0 挂。本课记号：**过＝通过，挂＝查出问题拦下，崩＝程序自己出错停了**）。但数据面的规矩是：**别人的体检不能代替我的体检**。道理很实际——万一货在半路被换过、万一造数方（＝生成这批数据的 fieldforge）的体检标准比我松、万一两边的"合格"根本不是一个意思呢？

所以 dp3（transform.py）自己备了 **20 条规则**，货进门先过闸：合格的批次放行，不合格的行当场剔掉，并开出数据面自己的体检单。本课拿上一课说过的**脏配方产物当靶子**（fieldforge 的 tpa_s1_dirty 配方，故意往干净货里掺 10 类错），实弹打一遍，看 20 条规则真接得住几条。

## 2 调用链：闸有两道，一道管进门、一道管全景

```
run 目录的 CSV（1-1 的货）
   │
   ├─▶ 闸 A：行级闸 validate_batch（4 条规则，管"每一行干不干净"）
   │        入口：31,774 行 → 出口：31,379 行（剔 395 行）+ 体检单一张
   │        谁用它：入湖前（1-3 的 dp2 只收洗过的货）
   │
   └─▶ 闸 B：全景体检 validate_bundle（20 条规则，管"表和表之间对不对得上"）
            逐条规则出独立结论
            谁用它：批级体检/测试（本课打靶用它）
```

为什么分两道？行级规则快——一遍扫过去每行独立判断，适合卡在入湖门口；跨表规则（"油表里的井号必须在档案表里""月结算和月产量对得上账"）要把多张表凑齐才能算，适合做批级全景。

（同一东西的几个叫法，对照此句：**行级闸＝闸 A＝代码里的 validate_batch；全景体检＝闸 B＝validate_bundle**。课文交替使用。另外"键"这个行话先说清：**键＝井号+日期这对身份组合**——"同键"就是同一口井同一天。）

### 站 1 一条规则长什么样（`transform.py:22-28`）

```python
@dataclass(frozen=True)
class QualityRule:
    rule_id: str
    name: str
    dimension: str
    check: Callable[[Rows], list[Locator]]
    check_batch: Callable[[dict], list[Locator]] | None = None  # S2 bundle 形态
```

大白话：一条规则＝**编号 + 名字 + 挑哪个维度的错 + 一个判据函数**。判据函数吃一行行数据（Rows＝列表，每行是一个字典），吐出"错在哪"的定位器列表（Locator＝写明哪口井哪天的定位条）。最后那行 `check_batch` 是给"全景体检"用的第二判据槽位（S2＝设计文档里的第二期工程档位；那行类型签名现在读不懂没关系，记住"一条规则最多带两个判据函数"就行）。20 条规则就是 20 个这样的对象，全列在 `transform.py:389` 的 RULES_FULL 清单里。

看一条真规则——rule-1 唯一性（`transform.py:49-56`）：

```python
def _dup_well_date(rows: Rows) -> list[Locator]:
    seen, dups = set(), []
    for i, r in enumerate(rows):
        key = (r.get("well_id"), r.get("prod_date"))
        if key in seen:
            dups.append({"_index": i, "well_id": key[0], "prod_date": key[1]})
        seen.add(key)
    return dups
```

大白话：拿个本子（seen）记见过的"井号+日期"组合；同一组合第二次出现，把后那行的行号记下来。一条规则十几行，没有魔法。

### 站 2 行级闸怎么放行/拦截（`transform.py:103-125` 原文）

```python
def validate_batch(table: pa.Table, rules: list[QualityRule]) -> tuple[QualityReport, pa.Table]:
    """质检闸：返回 (QualityReport, cleaned_arrow)。不合格行从 cleaned 剔除（保留首条）。"""
    rows = table.to_pylist()
    failures: list = []
    rule_ids: list[str] = []
    bad_index: set[int] = set()
    for rule in rules:
        rule_ids.append(rule.rule_id)
        locators = rule.check(rows)
        if locators:
            failures.append((rule.rule_id, *locators[:5]))
            for i, r in enumerate(rows):
                for loc in locators:
                    if "_index" in loc:  # 行级精确定位（重复出现剔除保首条）
                        if i == loc["_index"]:
                            bad_index.add(i)
                    elif "well_id" in loc and \
                            (loc.get("well_id"), loc.get("prod_date")) == (r.get("well_id"), r.get("prod_date")):
                        bad_index.add(i)
    report = QualityReport(passed=not failures, failures=failures, rule_ids=rule_ids)
    clean_rows = [r for i, r in enumerate(rows) if i not in bad_index]
    cleaned = pa.Table.from_pylist(clean_rows, schema=table.schema)
    return report, cleaned
```

四步读法：①把表拆成一行行；②逐条规则挑错，错的记账（定位器最多留 5 个例——报告是给人看的，不用罗列几千条。代码里 `*locators[:5]` 的星号＝"把列表拆开塞进去"，`[:5]`＝最多取 5 个）；③把错行标记出来；④**没被标记的行重新装表，跟体检单一起交出去**。注意剔除有两种精度：带行号的（重复行）**只剔那一行、保住首条**；只有"井号+日期"的（值域＝取值范围出界的错）**同键全剔**——同一天的数据有一行超标，这口井这天就都不认了，宁严勿漏。

**实测（脏货过行级闸）**：31,774 行进 → 31,379 行出，剔 395 行（同键重复的行 + 折算密度出带的行），体检单结论 `passed=False`（false＝没通过）、报告编号 `570d1f70...`。报告编号有什么用？它跟着货进湖（站 4），以后任何答案都能说出"我的数据过的是哪一份体检"。

### 站 3 实弹打靶：20 条规则的成绩单

成绩：直接真跑的 18 条里，**干货 17 过、1 挂（rule-12）；脏货 11 挂、7 过**。剩下 2 条（rule-2、rule-12）的全景体检入口本身有 bug 跑不动（站 3 末细说）——上表这两条的结论是按各自判据手工补测的：rule-2 干货脏货都无空值；rule-12 干货挂（渤中 2025-09 差 10.87%）、脏货挂（差 10.96%）。

三个最值得带走的深读：

**深读一：一条错会连坐另一条规则，洗掉自动愈合。** rule-19 在脏货上挂：渤中 2025-10 结算净重 ÷ 区块月油量 = −5.26%，超 3% 红线。查成因：那个月根本没有单位误录行，真凶是 **rule-1 的重复行**——384 行重复把区块油量合计抬高了。把重复行剔掉再算：差值正好回到 **−2.00%**，一分不差落在设计输差上。这就是真实数据质量工作的样子：症状在 A 处，病根在 B 处。

**深读二：同名规则不同义——干货为什么也挂 rule-12。** 数据面 rule-12 查"注入≈产液"，而 fieldforge 造数时保证的是另一条（结算=产量×0.98）。`transform.py:249` 的注释把这事钉在了代码里：

```python
    """规则 12：区块月物质平衡 注入 ≈ 产液×(1±3%)。

    有意分歧注记：fieldforge r12 对齐"结算 vs 产量"，本仓按设定书 §4 原文
    "注入量≈产出量+存水率变动"对齐"注入 vs 产液"——两处不要互相"对齐"。"""
```

两边都没做错：造数方从没承诺"注入≈产液"，所以干净货也差 10.87%。（注释里"X vs Y"的读法＝"拿 X 和 Y 互相核对"。）教训：**跨系统对规则，对判据、不对编号**——两个"rule-12"根本不是一条规则。

**深读三：接住几类、漏掉几类，如实记账。** 造数端掺了 10 类错：8 类被对应规则正面接住（rule-1/3/4/6/7/8/9/10/13），1 类捎带接住（"配产双值行"以重复键的形式被 rule-1 拦下——1-1 看过的那两行 N-01），1 类**没人接**（"措施有效期 30% 缺失"——设计文档的指标卡备注里记了这一笔，但 20 条规则里没落这条）。闸门不是万能的，漏了什么要写在明面上。

### 站 3 末的挂账（"挂账"＝记下来待处理）：全景体检的入口本身没打过仗

打靶第一枪就卡了壳：**`validate_bundle`（`transform.py:414`，20 条一起跑的入口）一调真数据就崩**。两处崩因大白话：rule-2 的批级版，收到的本该是"多张表打成一个包"，代码却按"一行行数据"的用法去用它——必然崩；rule-12 碰到"井号在井档案里查无此人"的行（这种行有个行话叫**孤儿行**）时，排序环节要把"空"（None，编程里表示"没有值"的记号）和文字比大小——程序拒绝并报错。98 个测试全绿，是因为测试都是"逐条取规则、手工喂样本"，从没让 20 条整队走过这个入口。已记进 0-0 总纲"发现的问题"清单（编号 P4），整门课收官时统一开施工票（记待办修活的文件）修——**这就是"测试全绿"和"真能跑"的区别**，本课靶子替我们把它打出来了。

## 3 服务与中间件卡：自研规则对象，还是通用检查框架？

- **它替我们干了件什么体力活**：把"挑错的标准"写成代码，一键体检、自动出报告。
- **自研还是开源**：自研。但只自研了"判据"这一层——每条规则就是个纯函数，闸的骨架（validate_batch）一百来行。
- **市面上同类有哪些**：dbt tests（在数据工具 dbt 里用配置声明"这列不许空、这组合不许重"，复杂的写自定义 SQL）、Great Expectations、Soda——都是成熟的数据质量框架。
- **本项目为什么选自研**：20 条里大半是**油田业务判据**（钩稽、物质平衡、状态滞后、补录批次时限），通用框架的内置检查（非空/唯一/值域）覆盖不了，硬塞进框架还不如十几行纯函数直白；且本仓按"最小可用"档位（设计文档叫 S1 档，0-0 提过）立了"不引入教学仓没承诺的框架"的红线，为一个闸拖进 dbt 全家桶不划算。
- **换场景怎么选**：通用完整性/唯一性为主、团队已用 dbt → 直接 dbt tests；业务钩稽、跨表口径多（油田正是）→ 自研判据对象更贴。两者也可混用：通用项交框架，业务项自研。

应看到 `passed=False`，行数账 **31,392 进 → 31,389 出，剔 3 行**。这 3 行的账要会算（本步最容易搞混的点）：

- 塞的"含水 150%"那行被剔（rule-5，应该的）；
- **N-02 那天的无辜原行也被连坐剔了**——rule-5 的定位器只有"井号+日期"，同键全剔：这口井这天的数已有超标的，索性整键不认（宁严勿漏）；
- 塞的 N-01 重复行被剔，**原行活得好好的**——rule-1 定位到行号，精确剔、保首条。

两种剔除精度（按键连坐 vs 按行号保首条）是闸的设计选择，不是 bug——回看站 2 代码 `transform.py:116-121` 的两个分支。

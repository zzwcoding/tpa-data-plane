## 1 这门课学什么

### 1.1 三件套的关系

- **teach-petro-agent**（教学仓）＝图纸：平台该长什么样，全是设计文档和伪代码。
- **fieldforge**（上一门课）＝造数器：按图纸批量生成以假乱真的油田生产数据——14 张 CSV 表 + 一份 manifest 说明书（manifest＝随数据附带的 JSON 文件，写明谁生成的、用什么随机种子、质检结论）。
- **tpa-data-plane**（本课）＝**数据面**，真代码。

"数据面"解释：一个智能问答平台拆两半——一半听懂人话、组织答案（服务端 + 大模型）；另一半专门管数据：存进来、查出来、算对、管住权限。后一半就是数据面。它是**确定性代码，没有 AI**：规则怎么写就怎么算，答不了就老实说答不了。

### 1.2 数据面干三件事（本课三个场景就按这三件事切）

1. **进湖**：外面的数据想存进来，必须过质检闸，合法批次才准入——不许任何人绕路改数据。
2. **问数**：有人问"渤南区块上月产量完成率"，要把这句人话翻成结构化查询，过权限闸、时效闸，真算出数。
3. **交代**：每个答案钉在数据版本（快照）上，随时能按原版本重算一遍对质；答不了的问题按固定话术诚实拒答，绝不编数。

### 1.3 高频术语（先记这五个，后面每个都在代码里见得到）

| 术语 | 一句话解释 |
|---|---|
| 湖 / 湖表 | 数据原样存进一个大池子，只追加、不修改（append-only：只能往尾部加，不能改旧数据）；湖表＝池子里一张有结构的表 |
| 快照 | 湖表每追加一批数据就自动拍一张"存照"，编号 0、1、2……查历史就是指定编号查那张存照 |
| 口径 | 一个数字按什么公式、什么范围算出来的规定。"产量完成率＝实际产油÷计划配产×100"就是它的口径 |
| 白名单、默认拒绝 | 只有名单上明写的组合才放行，名单外的全部拒绝 |
| 四件套 | 本仓给每个查询答案的四样东西：数字 + 快照号 + 质量状态 + 数据截至时间（少一样都不算合格答案） |

## 3 有哪些程序（一行一个）

|---|---|---|
| `app/data_plane/lake_store.py` | **dp1 湖底座**：数据池子本身——建表、追加、按快照查。故意不提供"修改/删除"入口 | 182 |
| `app/data_plane/ingest.py` | **dp2 进料**：唯一合法搬入口——先质检、再入湖、再登记数据时效；顺带管"新鲜度登记册" | 94 |

| `app/data_plane/semantic.py` | **dp4 语义层**：把"人话问句"翻成结构化查询；管术语黑白名单；管口径消歧 | 202 |
| `app/data_plane/semantic_dictionary.yaml` | dp4 的字典本：15 张指标卡（每张＝一个数字的口径档案）+ 术语表 | 217 |
| `app/data_plane/query_runner.py` | **dp5 执行适配**：真正算数的——闸→成本护栏→交引擎执行 | 55 |
| `app/data_plane/freshness.py` | **dp6 路由拒答**：决定"该不该答、答哪套数据"；答不了就按话术诚实拒答。⚠️ 文件名叫 freshness，干的却是路由的活（历史命名，本课统一叫它 dp6） | 156 |
| `app/data_plane/audit.py` | **dp7 审计回放**：每个答案钉在快照号上存档；随时按原快照重算对质 | 92 |
| `app/data_plane/tools_mcp.py` | **dp8 五工具**：对外唯一窗口——发现/描述/查询/回放/溯源，把四道闸串成一条流水线 | 144 |

| `serve/api.py` | **HTTP 壳**：把九个模块拼成一个网站服务（FastAPI＝Python 最常用的建网站框架之一），部署在云上 | 190 |

## 4 数据经过哪几步

### 4.1 设计全链（九个模块各就各位；本仓测试里真实跑通）

```
fieldforge（上一课的造数器）
   │  交付：一个 run 目录（14 张 CSV + manifest.json）
   ▼
① 质检 dp3   20 条规则逐行挑错，错行剔除，出"体检报告"
   ▼
② 入湖 dp2→dp1   合法批次写进湖，湖表长出新快照（编号+1）
   ▼
③ 翻译 dp4   "渤南上月完成率" → 结构化查询（指标+维度+时间窗+过滤条件）
   ▼
④ 治理闸 dp9   表间连线在白名单里吗？你的身份能看这个区块吗？
   ▼
⑤ 路由 dp6   数据够新吗？该答吗？答不了 → 按话术诚实拒答
   ▼
⑥ 执行 dp5   DuckDB（一个内嵌在程序里的分析数据库：不用另装数据库服务，直接读文件就能算）真算；查询太贵（要扫太多行）会被成本护栏拦下
   ▼
⑦ 记账 dp7   答案+快照号+口径版本存档，随时回放对质
   ▼
答案四件套：数字 + 快照号 + 质量状态 + 数据截至时间
```

### 4.2 云端现实（线上跑的 serve/api.py，和全链有两处不同）

```
fieldforge run 目录 ──✗ 不质检、不入湖，DuckDB 直接读 CSV 文件──▶ ③④⑤⑥⑦ 同上
```

- **dp1/dp2/dp3 没上云**：它们的逻辑在测试里验证（98 个测试含全链 e2e——e2e＝端到端测试，从进料到出答案一整条链一次跑通）；云上为了少一套存储依赖，让 DuckDB 直接读 run 目录文件。
- **新鲜度是写死的**：云上登记表固定写"三张表都是 offline 档、数据截至 2026-09-26"。
- **调用身份固定**：云上写死了一个管理员账号（账号名 service，归属写"总部"）。所以"换个人查别的区块会被拦"这类行级隔离实验，在云上演不了，要用本地进程内带不同身份做（场景 2-3 安排）。

（这两处差异是 0-0 就要交底的事：哪些代码在云上活着、哪些只在测试里活着，后面每步会反复对号。）

## 7 发现的问题（走线实测发现；按 MISSION.md 的学习规则——学习阶段不改生产代码——不顺手修，收官 4-0 转施工票修。施工票＝这个仓库记待办修活的方式，一张 markdown 文件一张票）

| # | 问题（大白话） | 实测证据 | 定位 |
|---|---|---|---|
| P1 | **线上回放功能完全用不了（每次都报服务器错）**：答案回放要靠"串着四道闸的执行器"重算，组装代码时误把"不带闸的裸计算引擎"接了过去——执行器会的方法，裸引擎没有，程序当场崩。英文报错原文的意思是"DuckRunner 这个对象没有叫 run 的方法" | 云端回放试 3 次全报错；本地复现同样崩溃 | `serve/api.py:123`（对照组：测试里的接法是对的 `tests/e2e/test_tracer_bullet.py:81`） |
| P2 | **日期窗塌缩，不报错但算错（最危险的一个）**：SQL 查询模板里预先挖了两个"坑"（占位符＝先挖好、运行时再填值的空位），本该一个填开始日期一个填结束日期；实际填充代码把两个坑都填了开始日期，结束日期永远没进查询——问"9-01 到 9-30 全月"，系统只算了 9-01 一天，还照常给你答案，没有任何告警 | 云端问全月返回渤中 94.2/渤南 94.9/渤西 92.3；本地同一份数据真算全月＝91.6/92.1/92.7，对不上 | `serve/api.py:75` |
| P3 | **没登记的指标：该给一句拒答解释，实际报服务器错**：语义层遇到字典里没有的指标会抛"查无此项"错（KeyError），但网站层只预先接住了另一种错误类型，这种没接住——用户看到"服务器出错"而非"该指标没登记"的解释 | 云端问一个没登记的指标"支持率" → 服务器错 | `semantic.py:146`、`serve/api.py:169-174` |

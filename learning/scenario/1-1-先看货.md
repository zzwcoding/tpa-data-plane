## 1 这一步做什么

数据面（tpa-data-plane）自己不造数据，造数据的活是上一门课的 fieldforge 干的。它交付的方式很朴素：**一个文件夹**。这个文件夹业内叫 run 目录（run＝"一次生成"跑出来的全套产物），里面是 14 张 CSV 表（CSV＝逗号分隔的表格文本文件，Excel 能直接开）加一份 manifest 说明书（JSON 格式＝一种"键: 值"成对的文本格式，机器好读）。

为什么这一步值得单独一课？因为数据面接下来的所有行为——质检挑什么错、新鲜度登记什么时间、答案敢不敢给——**出发点都是这份货和说明书**。看不懂货，后面每一站都是雾里看花。

所以本步实际是两件事：**看货**（结构：目录里有什么、说明书六段写了什么）+ **看交接规矩**（货怎么被认走——规矩是数据面的代码定的，但离开了货就讲不通，所以放在一起）。

**为什么把 manifest 叫"体检报告先行"**：货还没进湖，说明书里已经写好三样体检结论——格式合格没（conformance）、有没有故意加脏东西（injection）、闸门过没过（gate）。数据面后面就拿这些结论当"进料的凭据"。

打开 `/Users/divh/Downloads/fieldforge/out-tpa/manifest.json`，从上到下六段（下面全是原文节选）：

**① 身份段——这批货是谁造的**（`manifest.json:1-5`）：

```json
{
  "tool": "fieldforge",
  "version": "0.1.0",
  "python": "3.14.7",
  "generated_at": "2026-09-27T16:09:11+00:00"
}
```

连"用哪个版本的 Python 造的"都记了。这不是较真——fieldforge 说明书里写过：换 Python 大版本，同样的随机种子（seed，后面讲）也可能排出不同的数，所以版本必须入档。

**② 参数段——按什么配方造的**（`manifest.json:6-21`）：

```json
"schema":   { "name": "tpa-contract", "version": "0.1.0" },
"recipe":   { "name": "tpa_s1_demo", "seed": 20260927,
              "period": { "start": "2025-09-01", "days": 365 } },
"seed": 20260927
```

配方名 tpa_s1_demo + 种子 20260927——上一门课验证过：**配方 + 种子报给 fieldforge，就能一字不差重造这批货**。种子（seed）解释：造数要掷很多次"随机骰子"，种子就是骰子的起手牌——起手牌一样，后面每一次掷出的点数序列都一样，所以同配方同种子造出的货一字不差。另外注意周期起点是 **2025-09-01** 起一年，不是 2025 年 1 月——后面问数时"问 2025 年 9 月才有数、问 1 月没数"，根子在这行。

**③ 合成声明——自报家门**（`manifest.json:23`）：

```json
"synthetic_data_declaration": "本数据集由 fieldforge 生成的合成数据：仅可用于算法研发、测试、演示与教学；禁止用于储量申报、生产决策等任何真实业务场景。"
```

**④ 货单段——每张表多少行**（`manifest.json:24-95`，节选）：

```json
"entities": [
  { "entity": "well_info",            "file": "well_info.csv",  "rows": 120 },
  { "entity": "oil_production_daily", "file": "oil_production_daily.csv", "rows": 31390 },
  { "entity": "well_log_curve",       "file": "well_log_curve.csv", "rows": 288120 }
]
```

14 张表行数合计 **675,412 行**——正好对上 PRD 里的量级锚点"675,412 行"。

**⑤ 单位段——每个数字什么单位**（`manifest.json:96-147`，节选）：

```json
"oil_production_daily": { "oil_output": "t", "liquid_output": "m3",
                          "water_cut": "%", "open_days": "h", "oil_pressure": "MPa" }
```

油是吨、液是方、含水是百分比——单位错了比数字错还冤枉，所以单位单独入档。

**⑥ 体检段——三张体检单**（`manifest.json:148-170`）：

```json
"conformance": { "status": "pass", "checked_cells": 4603081 },
"injection":   { "enabled": false },
"freshness":   { "tier": "offline", "watermark": "T-1", "as_of": "2026-08-31" },
"gate":        { "overall": "pass", "summary": { "pass": 19, "warn": 0, "fail": 0,
                                                 "skipped": 6 }, "enforce": true }
```

四行各一句：格式体检抽了 460 万个格子全合格；没开"故意加脏"开关；第四行 freshness 是新鲜度登记（新鲜度＝"这批数据最新到哪一天、够不够新"的档案，1-4 专讲）——档位 offline（离线批，隔天到账）、水位 T-1（watermark，数据最多晚一天的意思）、截至 2026-08-31；第五行 gate 里的 `"enforce": true` 是 fieldforge 自己闸门的开关（检查不过就拦截交付，这只管 fieldforge 生成那头，数据面 1-2 另有自己的闸）。gate 的成绩单：**通过 19 项、跳过 6 项、不通过 0 项**。

**这里有一个本课要反复对号的"交底"**：说明书白纸黑字写着 `as_of: 2026-08-31`，但云端 API 里新鲜度是写死的"2026-09-26"（`serve/api.py:91`），e2e 测试里也是人手抄的"2026-09-26"（`tests/e2e/test_tracer_bullet.py:101`）。设计文档（`docs/prd.md` §6 供给契约表）承诺的是"manifest 的体检结论自动喂给数据面"，而现在的实现是**人看了说明书、手动填进代码**——"没接线"说的就是这个：设计有、代码还没做到。这个差距 1-4 会正面讲。

### 站 3 货怎么被认走（取货人读货的规矩）

> 先说清：取货人的代码住在数据面那头，不属于数据源。放在本步讲，是因为"结构"要配上"读法"才完整——说明书是写给取货人看的，认货、挑货的规矩全是他定的。取货人真正干活（质检、入湖、查询）在 1-2/1-3/2-5，这里只露个脸。

两段真实代码：

**云端取货人**：`serve/api.py:24` 先问环境变量（环境变量＝启动程序时从外面塞进去的设置项）要货位，没给就默认 `/data/runs`：

```python
RUN_DIR = Path(os.environ.get("DP_RUN_DIR", "/data/runs"))
```

然后 `serve/api.py:102-110` 的 `_latest_run()` 在货位里挑"名字排序最大"的子目录当最新一批货：

```python
def _latest_run() -> Path | None:
    """兼容两种目录形状：run 本体（含 manifest.json）或 runs 父目录（子目录各一个 run）。"""
    if (RUN_DIR / "manifest.json").is_file():
        return RUN_DIR
    if RUN_DIR.is_dir():
        runs = sorted((d for d in RUN_DIR.iterdir()
                       if d.is_dir() and (d / "manifest.json").is_file()), key=lambda d: d.name)
        return runs[-1] if runs else None
    return None
```

大白话：认货的标志＝**目录里有 manifest.json**；挑货的规则＝**按目录名排序拿最后一个**。这里有个要记的坑：按"名字"挑不等于按"生成时间"挑——实测云端现在挂的货是 `tpa_s1_dirty-20260928-022605-6763c0`（脏配方那批。脏配方＝fieldforge 里另一个配方 tpa_s1_dirty，故意往干净数据里掺 10 类错误、专门用来测闸门，上一门课用过；它不是因为它新才被选中，纯粹是名字排序靠后）。选货规则这么简单，是因为本仓只承诺"最小可用"档位（设计文档里叫 S1 档）——能跑，但确实会选错，这里如实记下。

货挑定后，`serve/api.py:40` 的查询模板直接对文件下手（read_csv_auto＝DuckDB 的"自动认表格"读文件命令，2-5 细讲）：

```sql
FROM read_csv_auto('{run}/oil_production_daily.csv') p
```

**教学全链取货人**：`tests/e2e/test_tracer_bullet.py:24-26` 把货位写死成上一门课的产物目录：

```python
FF = Path.home() / "Downloads" / "fieldforge"
RECIPE = FF / "recipes" / "tpa_s1_demo.yaml"
RUN = Path.home() / "Downloads" / "fieldforge" / "out-tpa"
```

`tests/e2e/test_tracer_bullet.py:38-42` 还留了一手：货丢了就按"配方+种子"重造一批（字节级一模一样，所以敢这么干）：

```python
def _ensure_fresh_run():
    if all((RUN / f"{t}.csv").is_file() for t in NEEDED):
        return
    subprocess.run(["python3", "-m", "fieldforge", "generate",
                    "--recipe", str(RECIPE), "--out", str(RUN)],
                   cwd=FF, check=True)
```

这就是上一门课"同种子同输出"的直接红利：**数据面丢货不用找货，照配方再造一批就是同一批**。

## 3 服务与中间件卡：「文件即接口」

五个问题走一遍（这卡的"部件"不是软件，是一个接口决定）：

- **它替我们干了件什么体力活**：让造数器和数据面两个程序不装任何共享软件就能交接——货放文件夹，说明书随货，谁来谁取。
- **自研还是开源**：交接约定是自研的（表结构来自 tpa-contract schema——schema＝表结构的正式定义文件；交接形态＝CSV/Parquet 加 manifest，Parquet＝另一种更省空间的表格文件格式）；读文件用的 DuckDB、PyArrow 是开源件（后面各步有各自的卡）。
- **本项目怎么配置使用**：造数方 `--out` 指哪算哪；数据面用环境变量 `DP_RUN_DIR` 指货位，`_latest_run()` 按目录名挑最新。
- **市面上同类有哪些**：①直接写进对方数据库（要连网、要账号、要建表）；②消息队列推送（要常驻中间件）；③HTTP 接口现做现取（要对方活着）。文件交接是最土的一种。
- **本项目为什么选它**：三个现实理由——①零依赖：不用为交接多养一个软件；②可复现：货丢了，配方+种子随时重造一批一模一样的；③人能直接看：Excel 就能打开。架构图 v1（`docs/architecture-v1.md` 节点表）里那句"FF 不入湖（边界在文件+manifest）"说的就是这个决定——FF 是架构图给 fieldforge 起的代号，"不入湖"＝fieldforge 的货不直接写进数据面的湖（湖＝总纲讲过的只加不改的大数据池），交接止步于文件和说明书。
- **换场景怎么选**：数据要实时（秒级）就得换别的交接方式——CDC（变更数据捕获：数据库一有新写入就自动往外推的技术）或消息队列（程序之间传件的"传送带"中间件）。dp2 代码里留了个空壳函数 `cdc_pipeline_spec`，就是给"哪天要实时了"占的位，现在不干活；一天一批的量级，文件交接刚刚好。

## 4 防线对号

- **合成数据自报家门**：manifest 第 23 行的声明、云端 API 每个响应都带的 `X-Synthetic-Data` 头、FastAPI 服务描述里的"禁止用于真实业务"——三处同一句话。这批数据以假乱真，唯一的"防误用闸"就是处处自报"我是假的"。
